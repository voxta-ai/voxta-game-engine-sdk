# Voxta Unity SDK Development Plan

**Status:** Active  
**Package root:** `unity/`  
**Unity baseline:** 2022.3 LTS / .NET Standard 2.1  
**Primary design:** [VOXTA-GAME-ENGINE-SDK-DESIGN.md](VOXTA-GAME-ENGINE-SDK-DESIGN.md)

## Reference implementations

| Reference | Path | Use in this SDK |
|---|---|---|
| Canonical client behavior | `G:\voxta-projects\GitHub\voxta-server\src\client\Voxta.Client` | Protocol behavior, message lifecycle, retry behavior, device flow, and speech playback semantics. It currently targets .NET 10 and is not a Unity runtime dependency. |
| Unity SignalR implementation | `G:\voxta-projects\GitHub\voxy-desktop-companion\Assets\Voxta\Voxta.Client` | Port and adapt its Unity-compatible SignalR setup, JSON configuration, main-thread dispatch, reconnect handling, and IL2CPP practices. Do not bundle this Voxy client as a dependency. |
| Unity linker configuration | `G:\voxta-projects\GitHub\voxy-desktop-companion\Assets\link.xml` | Starting point for the BasicIntegration sample's `link.xml`; Unity only consumes linker files under a consuming project's `Assets` tree. Validate it in a clean IL2CPP build. |

The SDK owns its transport implementation under `Runtime/Transport/`. It bundles only the pinned third-party SignalR and System.Text.Json dependency closure required by that implementation.

## Working agreement

- Treat this as the implementation checklist. Mark a task complete only after its stated verification has passed.
- Keep the checked-in DTOs generated from the pinned Voxta server revision. Do not hand-edit generated protocol files.
- Preserve Unity main-thread boundaries: callbacks from networking code must be queued before they invoke Unity APIs or UnityEvents.
- Keep new work within the active milestone unless a prerequisite blocks it; record newly discovered protocol facts in the protocol contract document.

## Architecture decisions

- [x] Keep the UPM package root at `unity/`; `package.json` is the installable package manifest.
- [x] Target Unity 2022.3 LTS and .NET Standard 2.1 for the public runtime.
- [x] Reuse the server client SDK as the protocol and behavior reference, not as a directly referenced assembly.
- [x] Generate and vendor the client protocol DTO subset from a pinned `Voxta.Model` build.
- [x] Use the Unity-proven SignalR 8.0.2 / System.Text.Json 8.0.0 dependency family, rather than the server SDK's current .NET 10 dependencies.
- [x] Ship managed dependencies and `link.xml` in the package so consuming projects do not need to configure a NuGet scoped registry.
- [x] Use Voxy's Unity client as a source reference only; the SDK owns and ships its adapted transport implementation.
- [x] Keep the published package ID as `com.voxta.game-engine-sdk`.
- [x] Set the initial shared package version to `0.1.0-pre.1`.

### Speech playback implementation status

The Unity implementation and generated protocol expansion are verified by a
live-server run: URL download, audible `AudioSource` playback, per-chunk start
metrics, natural completion, received `audioGapMs`, and both interruption paths
completed successfully. Automated runtime tests also cover completion
acknowledgement and interruption state transitions without an audio device or
HTTP decoder. The current local-server debugging established these contract facts:

- A `VoxtaSpeechPlayer`, enabled `AudioSource`, and exactly one enabled
  `AudioListener` are required in the scene.
- The player advertises `audioOutput: Url` only when that local playback path
  is configured. A local server can still choose its Audio Output service when
  `PreferClientCapability` is false.
- Deferred `/api/tts/gens/{id}` URLs have no extension. Unity therefore
  advertises and requests `audio/x-wav`, and decodes the response as
  `AudioType.WAV`.

- [x] Implement `VoxtaMicrophone` capture, PCM16 conversion, and audio-stream WebSocket startup frame.

- [x] Surface speech-recognition and VAD/audio-frame events.
